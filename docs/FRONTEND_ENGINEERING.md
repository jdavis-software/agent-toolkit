# Frontend engineering

Twenty-five original procedures cover React architecture, rendering and state; TanStack Query; Next.js and Server Components; Tailwind; design systems; responsive layout and accessibility; forms; URL/data/error boundaries; storage/workers/performance; testing, visual review and security; motion/refactoring; icons; design briefs; and headless component integration.

`skills/*/SKILL.md` remains the canonical instruction body. Every new package includes an original `references/recipe.md` and three **not-run** host evaluation inputs. The package registry is not evidence that an agent reliably applies every instruction.

## Find the right starting point

- **Modern React Applications** (`modern-react`) covers the implementation path from component/state ownership through server/client boundaries, queries, forms and usable interface states.
- **Frontend Performance and Reliability** (`frontend-performance`) covers measured rendering, background work, storage, budgets, tests, security and behavior-preserving changes.
- **Interface Design Systems** (`interface-design`) covers the design brief, tokens, components, Tailwind, layout, accessibility, icons, motion and visual review.

The **Frontend Engineering** category is a primary catalog partition. Some new design-oriented skills belong in **Design & Communication** instead. Bundles overlap intentionally; resolving a bundle is not a request to load every instruction for every task.

```bash
node tools/bundle.mjs resolve modern-react
node tools/bundle.mjs resolve frontend-performance
node tools/bundle.mjs resolve interface-design
```

The resolver includes the explicit frontend fixture source list and documentation. It does not install React or execute the fixture. Generated files and node_modules are never part of that list.

## An actual, isolated React fixture

`evals/frontend/` is an optional, independently locked client-rendered example, not a new dependency of the Astro website. Its original interface uses **React, TanStack Query v5, React Hook Form, Tailwind v4 and named Bootstrap Icons through React Icons**. Package versions and transitive integrities are recorded in its **package-lock.json**, generated by npm without running dependency scripts. The repository's existing pnpm lock and website dependencies remain unchanged.

This deliberately separate fixture uses npm because its lock was generated and qualified in that standalone package. Do not regenerate the root pnpm lock with npm, copy these pins into a private application, or silently upgrade the existing product stack. No Next.js, Radix, shadcn/ui, Motion, Zustand or external API is installed by this fixture.

From a full checkout, after reviewing its package list:

```bash
npm ci --prefix evals/frontend --ignore-scripts
npm --prefix evals/frontend run check
npm --prefix evals/frontend run build
npm --prefix evals/frontend test
# Uses the toolkit's already installed Playwright, with its own explicit test registry.
pnpm exec playwright test --config=evals/frontend/playwright.config.ts
```

To inspect the fixture manually after building, run `npm --prefix evals/frontend run dev` and open `http://127.0.0.1:4343`. The server binds only to loopback and implements a tiny in-memory synthetic API. Create/favorite operations mutate that temporary memory, not a product, provider, account or persistent store. Do not expose it publicly or use it as a security architecture example. The automated browser cases intercept API traffic with independent controlled responses.

### What its tests can establish

The original checks cover URL parsing/serialization, runtime payload validation, workspace-key separation, scoped invalidation, actual query cancellation, in-flight deduplication, preserved stale data, draft and server-error handling, pending-submit admission, optimistic rollback, late search results, text rendering of hostile-looking labels, accessible icon names, keyboard refresh, themes, long text and responsive layout. Browser tests use desktop Chromium and an iPhone-sized Chromium emulation profile, not physical devices.

The build writes bundle metadata and raw/gzip sizes under `.build/`. The fixture's predeclared limits are **150,000 gzip bytes for JavaScript** and **12,000 gzip bytes for CSS**. These are this small example's limits, not a universal application budget or measured network transfer. They do not establish field Core Web Vitals.

Its mutation example serializes conflicting favorite writes within the current list. It is not an implementation of arbitrary concurrent collaborative rollback. Query keys are not tenant authorization. The create form resets only on accepted save; an edit form with background refresh needs additional dirty-value policy.

### What is not established

No live agent-host effectiveness, Next.js server deployment/RSC/hydration, real authentication, production authorization, actual IndexedDB migration, real Web Worker lifecycle, screen-reader certification, physical-device coverage, cross-browser pixel baseline, Motion/Radix/shadcn integration, or field performance is inferred from this fixture. Those remain task-specific qualifications described by the relevant skills. The public guide is a static worked explanation; it is not running the optional React fixture in the live Astro site.

## Icons, source and ownership

Use an existing coherent family when available. `icon-system-integration` covers named imports, bounded registries, accessible action names, decorative SVG handling, sizing, theme behavior and actual bundle inspection. React Icons' wrapper and its individual icon families have separate licensing considerations. The fixture uses only the Bootstrap family and retains its MIT notice from the upstream license blob `f95243911022df8e34bb8c73c87ef491ee1696cf`.

The fixture build assembles dependency notices from the installed packages plus that family notice. React Icons, React, Query, Hook Form and Tailwind remain external libraries. Their code and glyphs are not claimed as original toolkit work. No license grant is added for Jordan's original repository content.
