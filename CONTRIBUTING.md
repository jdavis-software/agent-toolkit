# Contributing

Start with an issue describing a repeated task, its current failure mode, and the smallest reusable artifact that would help. Avoid bulk imports and giant generic prompts.

A skill contribution needs a `SKILL.md`, a catalog entry, clear activation and non-activation cases, prerequisites, a procedure, expected output, failure handling, and a public-safe example. New packages start experimental. Include actual host/version and output evidence before proposing a validated status. Structural validation alone is not behavior testing.

Curated entries must link to official sources, credit their authors, explain a concrete use case and limitation, and remain distinct from original work. Adapted content must retain required notices and record source revision and changes.

Run the checks in `AGENTS.md`. Review the complete public diff, including screenshots, fixtures, metadata, and source links. Do not attach secrets or private knowledge-base exports. The repository's original-content license is not yet selected; contributions that require a license decision should wait for that decision.
